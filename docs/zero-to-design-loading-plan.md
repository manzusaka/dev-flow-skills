# zero-to-design 指令加载改动方案

本方案只处理指令的固定加载量和按需路由。现状与其他 Token 开销见 [Token 消耗分析](./zero-to-design-token-optimization.md)。本轮不改变阶段数量、用户批准门槛、方向与页面的交付要求，也不修改原型生成方式。

## 成功标准

1. 调用 `zero-to-design` 时，入口只包含全程必需的约束和选择当前流程所需的路由；阶段细则、长示例和产物模板不再作为固定入口加载。
2. 首次设计只读取当前阶段的流程说明；已有系统接入、完成后扩展和跨会话恢复不读取不适用的阶段。现有设计能力参考文件仍在实际需要时读取，不新增“一次读取全部 references”的步骤。
3. 原有行为可复查：项目与端目录边界、旧状态保护、已锁定决定、来源优先级、用户批准、可运行预览、`DESIGN.md` 和 `doctor.mjs` 阶段检查都不丢失。
4. 用相同输入分别对比首次设计和持续设计的完整任务总 Token；没有运行数据前，不承诺节省比例。

## 现状判断

改动前（提交 `5ecf4ef`）的 `SKILL.md` 有 779 行、73,847 字节。调用 skill 时它作为入口加载，其中同时包含七阶段执行细则、`01-product.md`、`02-references.md`、`state.md` 的长示例，以及已有系统和扩展模式规则。后续阶段的内容因此在首轮就占据上下文。

已有 17 个 `references/` Markdown 文件合计 42,844 字节，但 skill 已要求按阶段读取。它们不是固定入口开销；继续维持按需读取即可。将入口内容搬到新 reference 只是**延后加载**：完整首次设计最终可能读到大部分阶段文件，不能把入口减少的字节数直接当作完整任务节省量。持续设计跳过前四阶段，预期更直接受益。若会话保留历史，延后读取也可减少早期轮次反复携带未来阶段内容的量；实际效果仍以用量记录为准。

这是一张迁移目标表，不要求机械复制原文。迁移时删去同一规则在入口、阶段和参考文件中的重复表达；每条关键约束只保留一个权威位置。移动后要修正相对链接，并检查原有模板、脚本与 README 的调用路径。仓库的 skill 名称、frontmatter 调用方式、顶层 README 条目及 plugin manifest 均不变。

## 精简入口必须保留的内容

入口需足以在读取其他设计文件前作出正确路由：

- 根据用户意图确定新产品、已有系统、恢复或扩展；先确定本地项目和 `{end}`，再读取该端状态或写入产物。URL 只提供运行界面证据。
- 保持用户语言；用户明确要求及已获批设计决定优先；已有设计资产经核对后优先复用。
- 已有状态从当前阶段恢复，不能重跑已完成阶段；明确重启时先保护旧状态和产物。
- 只打开当前模式、当前阶段的流程文件，再按其中的链接读取适用设计能力；不预读未来阶段、全部 `references/` 或 `docs/case/`。
- 保留阶段 1/2 产物确认、阶段 3 方向选择、首屏/页面反馈和最终 `DESIGN.md` 批准等关口；阶段文件负责各自的详细判定。
- 阶段交接和完成前运行现有 `doctor.mjs`；文件失败与缺失时按当前阶段说明处理。

入口只列出路由表和以上不变量，不放七阶段产物清单、状态模板、长示例、各设计维度文件的全集表。详细技术栈、组件与平台规则放在其实际使用的阶段文件中，并保持既有优先级。

## 读取路径示例

| 请求状态 | 预期读取 | 不应为此请求预读 |
| --- | --- | --- |
| 新产品，开始产品定义 | 入口、当前端状态（若有）、`phase-1.md` | 阶段 2–7、方向/设计系统模板、全部设计能力参考 |
| 新产品，已批准参考，进入方向探索 | 入口、状态、已批准的阶段产物、`phase-3.md`、该阶段需要的设计能力与方向模板 | 阶段 4–7、其他平台参考 |
| 已有系统新增页面 | 入口、状态、已有设计来源、`existing-system.md`（盘点尚未完成时）、`phase-5.md` | 阶段 1–4 的访谈和方向模板 |
| 已完成系统新增组件 | 入口、状态、权威设计来源、`extension.md` 及适用的阶段 5/6 文件 | 新产品流程与无关打磨维度 |
| 恢复阶段 4 | 入口、状态、已锁定决定的来源、`phase-4.md` | 重新运行阶段 1–3 |

## 实施顺序与验证

1. **先建立路由与文件清单**：逐段标记原 `SKILL.md` 中的全程不变量和阶段内容，记录原位置到新位置。验证：每个原有约束都有唯一落点，所有模式和阶段都有可到达的入口。
2. **迁移内容并精简入口**：先建立阶段文件，再删入口中的对应段落；更新相对链接，保留设计能力参考文件的按需读取规则。验证：链接目标存在，模板与脚本路径可解析，`SKILL.md` 不再含长产物模板或阶段细则。
3. **做行为回归**：运行 skill-creator 的 `quick_validate.py`；检查 Markdown 链接；用新产品阶段 1、方向探索、已有系统新增页面、已完成系统扩展、阶段 4 恢复及最终固化等场景核对路由。`doctor.mjs` 与现有脚本测试应维持通过。验证：上述成功标准中的功能和保护规则均可观察到。
4. **对照 Token**：同模型、同任务输入与反馈，分别测首次设计和持续设计的完整任务用量，记录入口、阶段文件、设计能力参考、工具返回与生成产物的贡献。质量通过后再判断是否保留改动；不以静态文件大小替代实测。

本轮已实施入口精简与阶段文件拆分；完整任务的 Token 对照仍待实测。前一轮讨论过的参考数量、三个方向、批准展示方式等调整仍可单独评估；它们不混入这次指令加载改动，以便辨别两类优化各自的效果。页面数量与方向页生成器也不在本方案范围内。
