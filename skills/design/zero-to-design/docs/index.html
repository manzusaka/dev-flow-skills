一次真实的运行 · Pulse

以下所有产物都来自一次真实运行的完整记录：为 Pulse（一个面向独立开发者的数据看板）从 0 建立设计系统。每个产物都是真实文件，可以点开亲自体验——不是截图。

Phase 1 · 产品定义：把模糊想法问清楚

用户只说了一句"我想给独立开发者设计一个看板"，skill 通过 8 个关键问题把它收敛成清晰的产品定义。以下是这次运行的真实问答（节选）：

Q · 这个产品叫什么名字？Pulse
Q · 一句话定义它是做什么的？把收入、用户和事件数据汇成一个清晰的首页，每天早上 30 秒就能判断产品有没有异常。
Q · 最典型的用户是谁？全栈 / 后端工程师、独立开发者、一人公司创始人。
Q · 用户打开页面前的心智状态？"我的产品今天还好吗？"——30 秒内确认，排除坏消息，也许发现一个小胜利。
Q · 相比 Stripe / GA / 自建看板，最核心的差异点？每天早上主动告诉你今天的状态，而不是等你自己去挖。
Q · 界面应该传达什么氛围？Calm（平静）+ Speed（效率）
Q · 目标平台是？Web
Q · 是否已有品牌资产？没有

已经回答过的问题不会重复问；没答的由 agent 推断并标注"agent 推断"。产出 01-product.md。

Phase 2 · 参考收集：给出审美种子

Agent 根据产品定义动态推荐了四类参考，请用户逐个浏览，反馈整体感受和局部标注：

  • 同类型产品（清晰但不冰冷的数据看板）：Stripe Dashboard / Linear / Plausible Analytics / Fathom Analytics
  • 跨类型气质（Calm + Speed 怎么表达）：Notion / Kinfolk / Aesop / Monocle
  • 设计灵感库（布局与交互细节）：Mobbin / Awwwards / Godly
  • 字体灵感库（挑字体搭配）：Typewolf / Fontshare

这位用户很早就给了显式偏好。这些原话被原样记录，成为 Phase 3 的硬约束：

浅色模式，不要默认深色模式。不要紫色，不要蓝色做主色，不要渐变。继续。

Phase 7 · DESIGN.md 固化

draft 固化为最终设计系统：多章结构覆盖设计灵魂、Tokens、组件规范、UX 约束、红线规则和 Agent 使用指南。它是后续所有页面开发的唯一视觉事实来源——AGENTS.md 会引用它，新 session 的 agent 开工前必须先读它。以下是真实文件的开头两章：

## 一、设计灵魂

Pulse 是一个面向独立开发者的数据看板。它的视觉风格是"编辑式平静"：
像一份排版精良的晨报，用细线、留白和信息密度建立秩序，
而不是堆叠卡片和装饰。目标是在 30 秒内缓解
"我的产品今天还好吗？"这种底层焦虑。

色彩策略：暖浅灰底 + 深炭黑文字 + 森林绿强调色。
绿色代表"正常 / 健康"，只出现在状态和正向变化上；
警告和错误用低饱和的暖棕 / 赭红，不刺眼。

字体分工：大标题用 Source Serif 4 带来人文编辑感；
正文用 Manrope 保证数据可读性；
等宽用 JetBrains Mono 处理金额、百分比和时间戳。
数字本身就是主角，不需要图表。

## 二、Tokens（节选）

| 名称     | Token              | Role                             |
|----------|--------------------|----------------------------------|
| 页面背景 | --bg-page          | 页面底色，营造暖纸感              |
| 主文字   | --text-primary     | 标题、大数字、正文强调            |
| 强调色   | --accent           | 品牌标识、正向状态、主操作        |
| 卡片表面 | --surface-card     | 卡片、导航、操作项背景            |
| 浅边框   | --border-subtle    | 细线、卡片边框、分隔线            |

Role 使用规则：--accent 只做点缀，禁止用于大面积填充……
