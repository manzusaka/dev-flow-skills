# 阶段 2

**目标**：让用户从“不知道想要什么”走到“知道喜欢什么、不喜欢什么”。

**执行方式：**

1. **先邀请用户推荐**：询问用户是否有想参考的竞品或其他产品；用户可以提供名称、链接、截图或具体页面，最好说明想借鉴或避免什么，也可以直接跳过。代理核实其产品、页面和目标平台，分析可借鉴点与不适用点；只有名称时由代理查找。无法核实时请用户补充线索，暂不计入最终参考清单或有效反馈。用户推荐先作为候选，不能直接当作设计要求。

2. **代理补齐推荐**：根据阶段 1 的产品定义和用户推荐，整理共 5–10 个参考供用户筛选。核实后入选的用户产品按类别占用同类或跨品类名额，代理补齐不足的数量；未入选的候选也记录原因。**参考类型须与阶段 1 确定的平台匹配**：
   - **移动端或原生应用**：推荐真实移动应用（App Store / Play Store / 官方落地页）及移动应用截图集合，不要默认推荐桌面网站。
   - **Web 或桌面产品**：推荐网站及以 Web 为主的设计图集。
   - **所有平台**都要覆盖下列四类；字体灵感库不是可选项。最终清单中的每项参考必须给出可直接访问的域名、商店链接或具体页面 URL，不能让用户自行搜索：
     - 2–3 个同类产品（直接竞争者）
     - 2–3 个气质相近的跨品类产品或体验
     - 2–3 个适合目标平台的设计灵感图库
     - **1–2 个字体灵感库，单独列出**：如 Typewolf、Font Pair、Fontshare；说明用途，例如看真实字体搭配或找可免费商用的字体。配色工具如 Coolors 可另列，不能充当字体灵感库。

   下表仅供选取候选；最终每项都附可直接访问的页面或商店链接。移动应用还须提供应用商店或移动截图来源，不能只给桌面版营销网站。

3. **向用户收集截图和整体感受**：请用户打开最终参考清单，分别回答两层问题；用户已说明具体借鉴或避免点的，不要重复追问：
   - **整体层面**：这个应用/网站/体验整体给人什么感觉（专业、温暖、大胆、平静、活跃、高级、亲近或其他）？希望自己的产品借鉴其中哪部分？有哪些整体气质明确不想要？
   - **具体截图层面**：截取 1–2 个喜欢或不喜欢的页面/局部，并说明具体原因（颜色、字体、布局、动效、文案、间距、图像风格等）。

4. **提供快捷路径（用户没时间逐个查看时）**：明确提供下面两种自然语言回答方式，**不要**额外追加 A/B/C 字母选项：

   > 如果没时间逐个看，可以直接用自己的话回复：
   > - “直接继续”——我会从同类产品的共同气质推断审美边界，整理参考文档供你核对；你确认后再进入阶段 3 生成方向。
   > - 或先说出明确偏好，再说“直接继续”。例如：“不要红、蓝、紫或渐变；用衬线字体。直接继续。”也可以说：“干净的黑白底，加少量亮色点缀。直接继续。”

   不要在这段说明后再添加“A. 查看网站 / B. 快捷继续 / C. 让我推断”等选项。用户应直接用自然语言回答。用户明确说出的“必须保留／必须避免”等偏好，无论来自正常反馈还是快捷路径，都按原话写入 `02-references.md` 的“明确偏好”；阶段 3 将其视为**硬约束**。推荐产品本身不是硬约束。

5. **整理文档**：把用户推荐的候选、核实与筛选结果、代理补充的参考、用户截图、整体感受、局部标注和明确偏好写入 `02-references.md`。

**产物**：`docs/prototype/{end}/design/02-references.md`。所有章节标题和字段名须用用户语言（中文示例：“参考收集”“用户推荐”“Agent 推荐”“明确偏好”“用户标注”“提取的设计线索”）。

```markdown

- **核实结果**：<同类 / 跨品类；目标平台、可访问的页面或商店链接；无法核实时写明>
- **筛选结果**：<纳入最终清单及借鉴范围，或未纳入及原因>

## Agent 推荐
<代理补充的参考及原因；与入选的用户推荐合计 5–10 个，必须包含字体灵感库>

## 明确偏好（用户明确提出的要求或禁忌；没有则写“无”）
- **用户原话**：<例如“不要红、蓝、紫或渐变；用衬线字体”，没有则写“无”>

## 用户标注

### 参考 1：<名称>
- **平台 / URL**：<移动应用 / 网站 / 商店链接>
- **整体印象**：<整体气质，以及想借鉴和不想借鉴的部分>
- **截图 1**：<文件名>
  - 喜欢：<用户描述>
  - 不喜欢：<用户描述>
  - 可提取元素：<颜色/字体/布局/动效/文案>
- **截图 2**：<文件名>
  - 喜欢：<用户描述>
  - 不喜欢：<用户描述>
  - 可提取元素：<颜色/字体/布局/动效/文案>

### 参考 2：<名称>

## 提取的设计线索
- **整体气质倾向**：<根据整体印象归纳>

- **字体倾向**：<明确偏好（若有）及用户标注>

```

**收集完成条件**：满足以下任一条件：
- 用户对至少 3 个参考提供有效反馈：通常包括整体印象和截图标注；用户推荐的产品经代理核实，且用户说明具体想借鉴或避免的点时也计入，只有名称不计入；
- 用户选择快捷路径（“直接继续”或“明确偏好 + 直接继续”），且其明确偏好已按原话记录；没有明确偏好时记录“无”。

**批准门槛**：满足收集完成条件后，写好 `02-references.md`，向用户展示完整文件的入口和简短摘要，供其核对；根据反馈修改同一文件，直到用户明确确认整份产物，再进入阶段 3。“直接继续”只跳过逐条参考反馈，不代替文档确认。
