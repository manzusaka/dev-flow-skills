# 阶段 1

**目标**：通过 8 个关键问题，明确“要做什么”和“应该给人什么感觉”。

**执行方式**：在对话中逐步提问。推荐一次问一个，也可以一次问 3–4 个以提高回答效率；根据用户答案的详细程度调整。

**开放输入规则（必须遵守）：**

- 每题给出的选项只是帮助用户回答的提示，不是封闭的单选题。
- 每题都要明确允许用户用自己的话回答，例如在选项后补充“也可以直接描述你的想法”。
- 用户自己给出的答案与列出的选项同样有效，直接写进 `01-product.md`；不要强制归入某个预设选项。
- 用户已用自己的话描述时，不要反问“这算专业感还是创造感？”；原话比预设标签更准确。应复述并记录其描述。

**智能跳过**：用户最初或后续回答已明确覆盖的问题，不再重复询问，只需确认。只有回答清楚且无歧义时才跳过；“做得好看一点”仍需追问。

**提问呈现规则（必须遵守）：**

- 下方 0–7 仅是内部索引，不能向用户展示。实际提问从 Q1 起连续编号，不能有缺号。
- 已知信息放在不编号的确认区，与待答问题分开。不要让确认区和问题清单使用两套混乱的编号。
- 例如用户已说明“卖数字产品的网站”和“首页有推广及商品列表”，可先确认产品类型与浏览/购买目标，再只问尚不明确的产品名、用户、氛围等。

**缺失信息规则：**

- 用户明确跳过或未回答某项必答问题时，不要进入后续阶段再返回补问。
- 在阶段 1 内根据已有答案推断，写入 `01-product.md` 并标记 `agent-inferred`。例如独立创作者的数字商品平台可推断“温暖 + 专业”，B2B API 市场可推断“信任 + 高效”。
- 若对推断没有把握，在结束阶段 1 前只确认一次；不要拖到阶段 3。

**必答问题（按顺序；编号仅供内部使用）：**

0. **产品名称**：产品叫什么？后续设计文件会使用此名称。
1. **一句话产品定义**：用自己的话，而非正式口号，说明这是什么。
2. **典型目标用户**：最典型的一位用户是谁？其年龄、职业以及目前如何赚钱或销售？
3. **用户心理状态**：打开页面前，用户带着什么期待或情绪？例如好奇、怀疑、找工具、受人推荐。
4. **氛围**：界面最应传达哪 1–2 种感受？可从信任、高效、平静、兴奋、专业、温暖、轻松有趣、创造力中选，也可以自己描述。选项只用于解释含义：信任意味着可靠，效率意味着不浪费时间，平静意味着专注，兴奋意味着探索欲，专业意味着严谨，温暖意味着有人情味，轻松有趣意味着不那么严肃，创造力意味着独特且启发灵感。
5. **核心差异点**：与主要竞争者相比，最重要的一个区别是什么？只选最重要的一项。
6. **转化目标**：最希望用户在此页面完成什么动作？例如注册、下载、购买。
7. **设计约束**：
   - 平台：Web、H5、Web + H5、iOS、Android 还是 Desktop？只设计用户要求的端。H5 记录目标手机画布；iOS/Android 还必须记录设备形态（phone 或 tablet）。如果用户只说 iOS、Android 或“移动端”，追问一次是 H5 还是原生应用，以及主要设备形态；不能在阶段 1 结束时仍缺少形态。
   - 目标用户年龄段
   - 无障碍需求：例如色盲友好、屏幕阅读器、大字模式
   - 已有品牌资产：logo、颜色或字体（如有，请用户提供）

**按答案质量决定是否追问：**

- “和竞争者差不多” → 追问用户为何会选择这个产品。
- “受众很广” → 追问只能服务一种人时会选谁。
- “要好看” → 追问希望用户因此感到专业、可信、有趣、高级，还是其他感受。
- 心理状态含糊 → 追问用户第一次听到产品时，更可能觉得“我需要它”还是“这是做什么的”。

**产物**：在项目根目录创建 `docs/prototype/{end}/design/01-product.md`，包含产品名称、一句话定义、目标用户、用户心理预期、氛围关键词、核心差异点、转化目标、设计约束和阶段 3/4 的关键页面。所有标题与字段名都使用用户语言（中文示例：`产品定义`、`产品名称`、`一句话定义`、`目标用户`、`用户心理预期`、`氛围关键词`、`核心差异点`、`转化目标`、`设计约束`）。

**批准门槛**：8 个必答问题都有明确答案（用户回答或代理推断，推断需标记），且用户明确确认 1 或 2 个关键页面。两项均满足后，在 `docs/prototype/{end}/design/state.md` 和 `01-product.md` 记录页面，创建尚不存在的 `01-product.md`。向用户展示完整 `01-product.md` 的文件入口和简短摘要，供其核对；根据反馈修改同一文件，直到用户明确确认整份产物，再进入阶段 2。产物获批后无须另问“要进入阶段 2 吗？”

**阶段 1 → 阶段 2 的页面交接**：8 项完成后，提议阶段 3/4 应一起设计哪 1–2 个最重要页面。大多数产品先做 **1 个关键页面**；仅当两个页面紧密耦合、必须一起看才能判断设计语言时（例如聊天列表 + 聊天详情、商店首页 + 商品详情、卡片信息流 + 个人主页），才提议 2 个。询问用户是否接受或想换页面；最多 2 个。用户只选 1 个时，不得暗自加第 2 个。
