# 原生 Adapt：按设备与平台重构

先读取目标平台的 [iOS](ios.md) 或 [Android](android.md) 指引。记录原设计对设备、方向、手势和姿态的假设，再说明目标设备的任务与失效点。适配不是放大手机界面。

## 原生适配主张

- 根据当前可用窗口、方向、多窗口状态和输入方式选择结构，不只凭“手机”或“平板”标签决定布局。
- 可以重排或展示更多内容，但核心任务、当前对象和操作结果应保持可识别。

## 适配规则

- **手机到平板**：用 size class / window size class 决定结构；根据任务使用侧栏、双栏 list/detail、网格或 popover。分屏后的窄窗口也必须可用。
- **横屏与折叠屏**：重排区域和控件；Android 折叠屏检查铰链与姿态。只有任务本身要求时才锁定方向。
- **iOS 与 Android 之间**：转译品牌意图，重做导航、返回手势、系统控件、图标和主题角色；不直接移植另一平台的控件外形。
- **Web 到原生**：用平台导航和触控控件替代 Web 菜单、hover 与 px 字体；完成目标平台完整检查。

实现后检查 safe area/insets、键盘、手机与平板、必要的方向和分屏状态。能用模拟器验证的写明模拟器；触感、复杂手势和性能需要实机证据。把新的适配规则写入当前权威设计来源，受影响页面生成新预览版本。
