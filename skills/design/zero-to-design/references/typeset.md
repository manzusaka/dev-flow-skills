# Typeset：建立可读且有辨识度的字体层级

先读取当前已锁定的设计来源，确认字体身份；新产品阶段 4 尚无 `DESIGN.draft.md` 时，以获选方向和 `01-product.md`、`02-references.md` 为准。局部排版打磨应保留字体家族；若更换字体会改变方向身份，回到阶段 3 的方向决策。

## 两次独立检查

1. **视觉检查**：在目标设备上观察标题、正文、辅助文字、数字和操作标签的阅读顺序；检查长文本、缩放、本地化、字重和字体加载失败时的表现。先记录视觉判断。
2. **机械检查**：对可读取的 Web 源码运行 `node <skill>/scripts/scan.mjs --scope type --target <路径>`。把结果当作线索，结合源码与渲染确认；原生界面按 [iOS](native/ios.md) 或 [Android](native/android.md) 指引检查。

## 确定字体系统

- 说明 Display、标题、Body、标签或 Mono 的职责；每层记录字体、后备字体、字重、字号、行高和字距。
- 先用有限的层级、字重和尺寸建立对比，再考虑新增字体。字体须支持产品实际语言字符。
- 控制行长、换行、段落节奏和数字对齐；链接、按钮与说明文字都应可辨认。
- 在运行预览中检查标题断行是否保留语义、正文行宽是否便于连续阅读；数字成列时检查位数变化后的对齐，适用时使用等宽数字。H5 输入框聚焦后检查文字大小、缩放和可读性，按项目组件与目标设备调整。
- Web 保持 zoom 与用户字体设置可用；原生界面尊重 Dynamic Type 或系统字体缩放。
- 变更 token 后更新 `DESIGN.draft.md`，检查所有受影响页面。局部例外写入页面实现契约。

## 验证

在常见和极端内容下，主要信息先被读到；正文、表单和状态文案可读；机械扫描没有未经解释的发现。只为受影响页面生成新版本。
