# Adapt：按使用情境重新组织界面

本文件用于 Web（含移动 Web）和桌面网页。iOS/Android 原生界面改读 [原生适配](native/adapt.native.md)。适配是重新确定任务优先级、布局和输入方式，而非仅缩放像素。

## 先定义变化

列出目标宽度、设备和输入方式、用户情境、内容范围，以及现有页面在这些条件下失效的具体位置。桌面到手机通常需要重排信息、缩短初始视野、保留核心任务入口；手机到桌面可增加并列信息，但不应凭空增加工作流。平板可能需要混合布局；打印或邮件只有产品确有需求时才纳入。

## 设计规则

- 使用内容与容器需要的断点，不照搬固定设备尺寸；组件按所在容器适配。
- 视觉顺序、DOM 顺序和键盘/朗读顺序保持一致。窄屏导航保留当前任务与返回路径。
- 横向表格可考虑滚动、摘要卡或渐进披露，但不能丢失关键列及其表头关系。
- 用 `pointer`、`hover` 等能力查询处理混合输入；必需操作不依赖 hover。
- 图片选择合适尺寸与裁切，文字允许自然换行；检查 safe area、键盘弹出与触控热区。
- 检查可点击区域的实际边界，而不只看图标或文字的可见尺寸；在 H5 触控和 Web 键盘操作中验证目标是否易触达、互不重叠且焦点清楚。
- 自定义滑杆、拖拽和横向控件必须实际测试触控手势及取消/滚动冲突；截图只能证明布局。

## 验证

一次检查窄、中、宽视口、长内容、缩放、empty/loading/error、键盘与可用触控工具。报告证据来自模拟视口、合成触控还是实机，并说明未测试的设备。把响应式规则写入当前设计来源，只为受影响页面生成新版本。

## 不同画布的具体取舍

### 桌面 → 手机

将多列信息按任务优先级重排，保留主要动作、当前位置和返回路径；长侧栏可变为抽屉或紧凑导航，但不得藏掉完成任务必需的入口。高密度表格可按数据关系选择横向滚动、摘要卡或渐进披露。把 hover 才显示的说明和操作转成触控可见状态。

### 手机 → 平板与桌面

更宽的画布可以让相关信息并列显示，例如列表与详情，但不能仅把手机卡片拉宽。对大量内容确定扫描节奏、最大行长和容器宽度。平板可能同时使用触控和键盘；窗口被分屏压窄时仍应保持结构。

### 图片与区域

用响应式图片尺寸和裁切避免在小屏下载过大的资源；重要信息不能只存在于被裁掉的图像区域。适配 safe area、输入法、固定操作栏及浏览器缩放；明确哪些区域重排、折叠、滚动或保持固定。

对打印或邮件形态，仅在产品范围包含它们时另定内容与交互契约；不要把 Web 页面样式直接缩放过去。
