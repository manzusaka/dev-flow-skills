# Colorize：让颜色承担层级、语义与氛围

先核对 `01-product.md`、`02-references.md`、当前设计来源、tokens 和代表性状态。区分已锁定的品牌色、语义色与仍可调整的表面色。若颜色变更会替换整体方向，应回到阶段 3，不在局部打磨中悄悄重设计。

## 建立策略

描述色彩的情绪温度、主要对比关系、明暗范围和使用强度。按用途建立角色：画布与表面、主要/次要文字、操作/焦点/选中、边框、成功/警告/错误，以及确有需要的数据类别。可使用 OKLCH 调整新 Web 色板，但色相应由产品含义与已选方向决定。

- 主要操作的强调色应容易找到，不用于无关装饰。
- 彩色表面的次要文字也要按真实前景/背景配对检查。
- 语义色保持一致；数据不能只靠颜色编码，须有文字、形状或图案辅助。
- 暗色模式须单独设计表面层级和对比度，不机械反转浅色模式。
- 全局变化更新语义 tokens 与 `DESIGN.draft.md`，局部例外记录为 `Surface` 规则。

## 配色主张

- 决定一种颜色前，先指出它传递的信息、引导的操作或反馈的状态；没有明确职责的强调色应收回。
- 同一状态在各页面使用一致的色彩角色，并在实际背景上检验文字与状态是否清楚。

## 对比度与验证

核对实际计算颜色：普通文字至少 4.5:1，大字、控件边界和焦点标记至少 3:1；检查交互状态、遮罩、图片上文字及支持的主题。颜色应服务内容、状态或视觉世界，在安静、密集、错误、空状态下仍成立。
